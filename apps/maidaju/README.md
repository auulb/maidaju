# 麦搭局 · 本地演示

Vite + 原生 TypeScript 单页应用，将 AI-1 需求与菜单、AI-2 逐人餐盘规划、AI-3 核价与下单串成一个可操作流程。

## 启动

在项目目录执行：

```bash
cd apps/maidaju
npm ci
npm run dev -- --host 127.0.0.1
```

打开终端显示的本地地址，默认 `http://127.0.0.1:5173/`。若端口已占用，Vite 会选择下一个端口。

现有依赖已安装时直接运行 `npm run dev`。Vite 所需 Node 版本以已安装包的 `engines` 为准（锁定版本要求 `^20.19.0 || >=22.12.0`）。

## 演示流程

1. 建局：设置 6–20 人、总预算、城市与位置关键词。
2. 成员需求：称呼、主食份数、五种硬性忌口、个人预算上限及其他偏好。
3. 门店与菜单：搜索并选择模拟门店，加载模拟菜单。展开事实表查看预设属性，勾选确认后生成；也可以保留未知事实直接生成。
4. 候选方案：比较不同购物车的逐人餐盘、估算金额、共享餐品及约束检查。方案不足三套时不会凑数；无可行方案时显示冲突与建议。
5. 核价与模拟下单：查看模拟实付、逐人记账分摊、取餐方式；待确认事实需逐项接受，最终明确确认后才会创建模拟订单。
6. 查询状态：查看模拟服务返回的订单状态。刷新页面可以恢复当前标签页的流程；确认勾选不会自动恢复。

## 数据与边界

- 全程固定 MOCK 模式，无需 token，不调用真实 MCP，不产生真实订单。
- 只接入到店自取：`beType=1`、`orderType=1`；不传 `beCode`、地址或预约参数。
- 门店编码与 `MOCK-` 商品编码均为虚构。模拟属性由 `src/server/mcp/demo-data.ts` 显式设定，与真实商品信息无关。
- 价格内部使用整数分，界面转换为元。缺少价格显示待核价；属性未知时为 pending。
- 页面通过 sessionStorage 恢复当前标签页的会话；业务数据在服务端内存中，重启服务或热更新 API 模块可能清空。
- 修改需求、门店、菜单或事实会使候选、报价与未消费授权失效。
- 已提交的下单使用同一授权和幂等键；页面会锁定再次提交。创建结果不明时保留冻结状态。
- 当前为本地演示服务，不适用于公开部署或多人账户隔离。

## 开发命令

```bash
npm run dev        # 前端 + 内存 JSON API
npm run typecheck  # TypeScript 检查
npm run build      # 构建前端静态资源到 dist
npm test           # 测试（按需运行）
```

`npm run build` 只产出前端资源。API 当前由 Vite 的开发中间件承载，单独部署 `dist` 不能处理点餐请求。生产部署需要独立 API 服务和持久化存储。

## 入口文件

- `src/web/main.ts`：界面、表单草稿、状态恢复和确认交互。
- `src/web/style.css`：桌面与移动端样式，无外部字体依赖。
- `src/server/web-api.ts`：内存 API 及三模块组合。
- `src/server/mcp/demo-data.ts`：演示门店、菜单、明确设定的事实。
- `vite.config.ts`：路径别名与开发 API 中间件。

API 统一响应 `{ ok: true, data }` 或 `{ ok: false, error }`。调用 `/api/sessions/:id/…` 时使用最新 `revision`；不存在的资源继续使用 `VALIDATION` 与 `details.notFound=true`，不扩展冻结契约。
