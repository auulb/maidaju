# 麦搭局 2.0 · 三种吃法，一起搭好

Vite + TypeScript 点餐应用。将 `maidajuSkill/SKILL.md` 中的选餐规则实现为本地代码：顾客点选人数、预算、逐人忌口和偏好，算法生成「多元体验 / 健身活力 / 能量满格」三套组合。

应用流程不使用 AI、语义识别、网络检索或 Python 子进程。所有计算也可在静态站点的浏览器中执行。

## 启动

```bash
npm ci
npm run dev -- --host 127.0.0.1
```

打开终端显示的地址（默认 `http://127.0.0.1:5173`）。Node 版本要求 `^20.19.0 || >=22.12.0`。

## 怎么用

1. 设置 1–20 人、总预算或人均预算；支持人数快捷按钮。
2. 选择到店自取、得来速、麦乐送或企业团餐；外送需填演示地址。
3. 用「N 人不吃辣」「全员无糖」等按钮批量设置，再逐人微调忌口、主食份数、预算上限及偏好。
4. 选择演示门店并加载菜单；可按主食、套餐、小食、饮品、甜品筛选，查看套餐默认搭配。
5. 比较三种方案的总价、人均、营养和餐品结构；切换购买清单 / 逐人餐盘，查看共享小食参与者与分摊。
6. 选择 A/B/C 复核价格，显示计划价与复核差额；可复制清单。默认到此结束。另有明确确认后才能调用的模拟下单流程。

预算不足、素食主食不足、没有合适饮品时会显示冲突和调整入口。只有一套不同购物车可行时如实展示，不复制凑数。

## 算法

`src/modules/planning/optimize.ts` 实现确定性的多起点搜索：

- 枚举成员合法主食组合，补一份饮品；套餐的默认主食、小食、饮品均计入份数。
- 按人数、预算、交叉忌口筛选；共享小食只分配给允许食用的成员。
- 从便宜可行解出发，进行逐人替换、共享项加购/删除/替换，以及固定种子的模拟退火和两人组合交换。
- 三个目标分别计算品种多样性、蛋白/脂肪/碳水/无糖、热量；热量和脂肪上限为软惩罚，不冒充医疗或营养保证。
- 团餐额外尝试跨过满折门槛，预算按活动后实付约束。满减/满折不叠加，排除商品不享优惠。
- 每个购物车再经独立检查器验证预算、忌口、每人主食与饮品、数量分配守恒；相同购物车去重。
- 默认最多 20 万节点、2 秒。固定输入及同一搜索范围可复现；大空间为相对最优的启发式结果，不承诺全局最优。无加购且小于 1 万组合的空间进行穷举。

逐人餐盘在搜索时直接分配，防止只有总量满足、实际有人拿不到合适餐品。套餐默认分给同一成员；共享小食均摊、订单优惠/费用按金额比例分摊，整数分尾差按固定成员顺序分配。

## 计价与数据边界

- 19 个餐品，商品、门店、价格、配送、活动与订单均为**演示数据**，不连接真实账户、不产生真实订单。
- 营养读取 `maidajuSkill/data/mcp_nutrition.json` 的已有官方 MCP 快照。鸡肉卷等缺失数据保留 `≈` 估算标记；套餐营养为默认组件相加。页面显示总量、人均、蛋白密度、脂肪、碳水、钠以及来源说明。
- 到店/得来速：菜单价，无配送费。麦乐送：菜单价 + 演示配送 ¥6 + 打包 ¥3。
- 团餐：原价 − 适用优惠 + 配送/打包。演示保鲜速达规则为满 ¥300 打 7.8 折、满 ¥500 打 7.4 折、满 ¥1000 打 7 折；轻享套餐不参与折扣。这是 Skill 阶梯规则的代码示例，**并非当前门店承诺**。
- 随单购卡价改用原价；缺少原价则待核价。套餐仅使用明确默认项；不可构建的套餐排除。
- 忌口依照明确的本地属性表；不从名称做语义判断。素食按蛋奶可、无肉/鱼建模；过敏原、清真等须向门店确认。
- 目前真实 MCP 的搜索/菜单入口仍保留到店自取边界；四模式完整体验由演示适配器提供，接入真实外送前需实现地址、门店业务编码、服务及促销的实时数据适配。

## 验证

```bash
npm run typecheck
npm test
npm run build
```

新增测试验证三目标差异与可复现性、1/2/6/12/20 人、交叉忌口、个人预算、无解、套餐、营养与数量守恒、小空间穷举对比、满折跳变/排除商品/满减、四模式核价分摊一致，以及静态后端真实 API 流程。真实 MCP smoke 测试默认跳过。

静态构建在没有 `/api` 服务时自动使用浏览器内模拟后端。Vite 开发模式的会话保存在服务内存，刷新可恢复；服务热更新/重启会清空。静态模式刷新后重置，不适合作为生产订单存储。

| `tests/planning/pricing.test.ts` | 计价及四模式核价验收 |
